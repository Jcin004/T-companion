# 人物衣橱 · 0.14.2

世界右上头像 → 人物，先选择人物，再进入其皮肤衣橱。对话立绘编辑入口直接进入对应人物的衣橱。已有皮肤、表情、步态和动作图片继续读取，无数据迁移。

衣橱卡片显示配套立绘、小人、名称和“使用中”。“使用”即时保存当前穿着；“编辑”只编辑该套资源。新增皮肤在独立名称对话框创建，改名与删除在卡片“更多”中。居民自主换装开关在人物衣橱，单套皮肤 AI 允许开关在卡片；用户“我”不显示 AI 设置。

编辑器顶部只保留标题、返回、关闭和三个独立分页：

- 表情立绘：选择平静、开心等表情，再上传或替换图片。未分类旧图和默认显示仍可在折叠项调整。
- 站立行走：首屏显示小人、播放/停止、方向和上传；行列、方向行、站立帧与顺序收在“调整图集”，保留切片预览。
- 交互动作：首屏显示浇水、翻书、阅读、整理床铺、开关灯、拉窗帘六类卡片。点击动作后独立预览和上传。未上传时使用基础动作，未新增世界规则。

切页保留草稿；返回或关闭有未保存内容时提示放弃，Android 返回也遵守同一处理。底部固定“保存修改”，保存失败保留草稿。保存前重读目录，只写当前皮肤，保留此期间切换的当前穿着和其他皮肤；同一皮肤已在其他编辑中修改时拒绝覆盖。异步读图与预览绑定人物、皮肤及页面，不接受迟到结果。

`character-looks-ui.js` 管理导航、草稿、卡片与原形象接口；`character-atlas-ui.js` 复用图片验证、图集布局和动画预览控件，不访问存储。原 CharacterLooksModule、SQLite 图片存储、世界显示和模型权限校验保留。无新增第三方代码、素材或依赖，继续采用暖木/奶油界面。

浏览器验收涵盖层级、分页首屏、名称错误清除、三类上传、使用/保存分离、失败恢复、当前穿着保留、固定导航、未保存返回、迟到文件隔离与重启。原世界表情/对话记录、视觉、行走和聊天返回回归保留，模型均为模拟。
