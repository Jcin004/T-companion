# 项目核心约定

更新：2026-11-07。每次规划、改代码和验收前先读本文。唯一活动迁入计划与证据见 [MIGRATION_PLAN.md](MIGRATION_PLAN.md)，历史实验见 [WORLD_PROBE.md](WORLD_PROBE.md)。

## 愿景和已确认方向

用户选择 C：持续存在的世界与独立自主的人物。人物的生活包括彼此、地点、活动和通信；用户可以是邻居或过路人，不自动成为人物生活的中心。

当前接受规则、概率和中断后的补算，体验后再判断是否需要更充分的自主。日常不每几秒调用模型。入驻时各人分别提出有限计划，程序校验后执行；相遇、收到消息、受阻、中断、重要活动/计划完成等变化再唤醒本人。不一次代写所有人的决定，不补造未指定职业、关系或身份。

首阶段以 e53790a 为基线，保留 T 的 Android、存储、现有人物/记忆/衣柜和像素呈现，按模块迁入 SullyOS 与 float。实验通过用于判断组合能力，不等于完整产品架构已经成立。

## 每批代码的复用要求

先查既有 T、用户仓库、SullyOS、float、Alicization Town、awesome-ai-companion 中的现成实现，优先取用已有代码。只有不适用的部分才写必要接口胶水与校验，并记录原因。

每个导入文件保留固定提交、原文件/blob、保留段、作者、许可、依赖、SHA-256 与适配差异。供应商原文放 frontend/vendor，不直接修改；外部适配和设计参考分开记录。当前来源清单：config/world-probe-sources.json、config/neighborhood-sources.json；既有衣柜和记忆来源记录继续有效。

本批实际使用 SullyOS 8035795 的 threads、ThreadBubbles、PhoneModal 消息源码段；A-Life b232809 的 Clock/GOAP/Schedule；T 已有 Alicization Town 寻路适配。SullyOS 全局 Context、DB 和逐角色家园模型循环不导入。float 预设/动作/插件/App 按后续批次接入，不能记为本批已完成。

## 数据所有者与接口边界

| 模块 | 唯一职责 |
| --- | --- |
| 人物名册 | 原人物 ID、Canon/Persona、用户指定设定，不复制为世界名册 |
| 世界 | 地点、位置、物品占用、实际行动、事件和知情依据 |
| 生活运行 | 计划、活动进度、到期任务、补算游标、唤醒、预算与恢复 |
| 通信 | 人物间消息原文在 SullyOS 线程，涉及用户的原文在原会话，世界事件只引用 |
| MemoryModule | 来源资格、提取、归纳、召回和认知消化；不建世界/手机平行记忆库 |
| 呈现 | 读快照、提交命令；不直接改领域数据或调用模型 |
| 持久化与宿主 | 原 SQLite 事务/CAS、QuickJS、WorkManager、恢复；网络等待不持全局写锁 |

送达、本人查看、回复选择和生成失败分开记录。观察人物手机不能代发、不标人物已读，也不给其他人物知情权。现场发言只有近处听众知道，私信只有参与者实际查看后知道。主观处境和人物陈述不会自动成为世界事实。

## 首阶段规则

- 三地点：暖木小屋、庭院、公共活动室，名称可改。保留原两居民，第三人从既有名册选择，未绑定第三人仍能使用。
- 每次计划 1–12 项已有活动，总时长不超过一天；校验地点和所需物品。程序执行移动、等待、开始/完成和占用冲突。缺计划、失败、受阻、完成待安排明确显示。
- 世界与现实时间 1:1，沿用应用时区，历史保存绝对时间；换时区不改历史。按到期点推进，Clock 不超过一小时分段，保留跨日修正。
- 长离线最多一天一批，保存游标继续追赶。模拟发生时间与实际生成/发送时间分开；新消息不能伪装为过去已送达。读页面不生成或推进。后续随机/塔罗必须抽一次存事件、重试复用，不能直接变成关系事实。
- 默认后台 30 分钟检查，每批最多 6 次自主模型请求，每日共享 24 次；主动聊天沿用原规则。额度耗尽规则继续，需模型的决定等待；离线规则也能执行。
- 安静时段抑制通知/向用户分享，不停止时间和活动。强停/关机由恢复补算承担；Android 间歇调度不承诺准点常驻。
- 模型在事务外提出候选，接受前重读并检查世界/人物计划版本。结果不确定不自动重发；已保存完整响应只重试接受，避免再次付费。

## 桌面与查看路径

首排固定世界、消息、人物；其他已有应用可排序。世界记录、记忆、相册、衣柜、外观、设置各自独立入口。尚未迁入的剧情和应用商店不放空图标。

世界顶部地点切换，中间像素场景，底部选中人物活动/交互。查看地点只改变相机，前往地点才移动用户。人物手机是独立全屏观察页，显示当前对象，不嵌一层小手机。

世界跳到人物手机、记忆、记录使用同一模块并带人物条件，返回保留地点和界面状态。人物手机变化不计用户未读，实际收到的原会话消息才产生用户未读。

沿用主题/字体，正文至少 16px、触控至少 44px，检查窄屏、长消息与大字体。复杂编辑使用独立上下文，确认和短操作才用弹窗，不连续堆叠。

## 升级、交付和后续

保留原人物 ID、聊天、记忆、形象、衣柜、旧暖木事件。世界和生活分别升级；SQLite 同一事务保存升级前原文与新状态，浏览器在同一 IndexedDB 事务备份。设置可导出旧备份，恢复支持旧/新格式；失败保留原数据。

隔离浏览器、Android 模拟器、旧 WebView 验证，模拟模型与真实服务分开记。每个验证通过版本按原试用渠道发布原签名 APK、匹配提交源码和清单。源码 PR 由用户决定合并。

后续顺序：SullyOS 剧情/记忆体验 → float 预设/动作 → float 插件/App 安装运行 → 电话、信件、家具制作。每批单独确定代码来源和验收。

待定：Warm 规划准确位置，塔罗映射、复杂建造/消耗规则、插件安装与权限、是否需要常驻宿主；真实模型的计划质量、持续生活感和预算体验。不能从未决项倒推补造人物设定。
