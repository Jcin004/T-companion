# 逐帧位置修复 · 0.18.3

基线 `1bc3186c4a3b970df97ef3626ccde9102055da50`，分支 `fix/isolated-sprite-frame-position`。包名与签名沿用原版，versionCode 29。

## 问题与修复

0.18.2 选中某格后，主预览仍默认移动整组校准；展开“微调选中姿势”会暗中改变拖动范围，而且整图导入但没有单独上传过的格子不能微调。这使“选中第二帧”不代表只修改第二帧，也无法修正原图第一/第三帧的相对偏移。

现在选中哪格，拖动就只修改哪格。展开或关闭数字微调只影响控件展示，不改变拖动对象。“同时移动所有姿势”默认关闭，明确勾选才能改整组落地；切格、切人物/皮肤或完成修改后恢复单帧范围。大小保留共同缩放并明确标为“整组大小”，单帧大小在数字微调内。

整张图上传的帧无需重新上传：首次编辑该格才从保留的原图等尺寸取出，按原像素比例记录为可编辑来源。只修改该格的平移/缩放，再经原合成入口生成图集；其他格、原图、整组校准不变。还原这一格会恢复原图对应区域。没有自动收紧透明边框或逐帧拉满画布，不靠更换锚点掩盖图片本身的偏移。

世界继续按同一个帧矩形、身体比例、脚底和世界位置绘制。预览采用固定素体/中心线/地面线，并在迈步帧拖动中保留站立帧叠影。已有素材的身体中心若不一致，可分别拖动第一帧和第三帧对齐站立帧；不会猜测或批量改写用户已保存的姿态。

## 使用

世界 → 头像 → 人物 → 皮肤 → 站立行走。点第二格后拖动只改第二格；点第一/第三格，参考半透明站立姿势对齐身体中心及脚底，播放行走检查，再保存。非对称衣服、头发和迈出的脚可以自然摆动，应比较躯干和落地点，不要求所有可见像素完全重叠。

整组身高统一用“整组大小”。确实想把全套图片一起移到固定地面时，勾选“同时移动所有姿势”再拖动。原有方向/行帧导入、单图替换、表情/动作分页、关闭/保存和未保存保护保留。

## 模块与兼容

- `character-frame-editor.js` 增加 `editableFrame`，仅按原行列取出当前帧，仍通过 `replaceFrame` / `composeFrames` 合成；保留原图和既有来源。没有新图片库、外部依赖或格式迁移。
- `character-atlas-ui.js` 负责选格、数字输入和草稿；未单独上传的格子也能调整。异步编辑沿用原人物/皮肤/代次校验。
- `character-calibration-ui.js` 明确单格与整组范围，指针取消不修改；双指仅缩放视图。折叠数字微调不再改变范围。
- 人物形象接口继续校验，原事务与 SQLite 保存整套资源；世界位置、事件、聊天与记忆规则均不修改。

本次复用现有切帧、图像缓存、单帧合成、校准与存储接口。继续遵守既有像素动画资料中的固定帧尺寸和统一锚点做法，无第三方代码或素材导入。

## 验证

新增 `tests/frame-position-browser.mjs`：合成 3×4 图集，故意让第一/第二/第三帧有不同横向留白。旧版拖第二帧会改共同 calibration，测试实际失败；修正版第二帧独立移动，另 11 格像素保持相同，第三帧调整也不改第二帧。分别对齐三个姿态后，世界绘制的四个播放阶段身体中心和脚底相同，验证切帧不横跳。

同一测试覆盖原图保留、整图中未单独上传格子的数字编辑、取消、展开微调不切范围、勾选整组后切格恢复单帧、保存重启。原衣橱、固定参照、单图上传、场景表情/记录和连续移动流程回归。Node/Python、Android 原生触屏和正式包验收结果在交付段补充。

测试只用合成图和隔离存档，不调用模型，不改真实用户素材。


验证通过：141 项 Node、103 项 Python（warnings as errors）、新增逐帧浏览器回归及原六组相关流程。专用 Android 11 / WebView83 使用原生触屏拖动第二/第三帧，另 11 格逐像素相同，原图保留；切格恢复单帧范围，SQLite 重启和原签名 28→29 覆盖保留完整业务/加密凭据指纹。结果 `artifacts/frame-position-native.json` 和原生截图 `frame-position-native.png` 留本机忽略目录。真机未测。
