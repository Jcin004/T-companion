# 暖木世界与底部对话 · 0.13.0

## 0.13.1 人物图片与站立步态修正

入口：世界右上头像 → 人物 → 顶部选择要修改的人物。该人物的两类资源分别保存在“对话立绘”和“像素小人”分页，各有上传/替换入口；顶部人物、分页和关闭按钮、底部保存按钮固定，只有中间内容滚动。立绘是底部对话框的大幅人物图片，可以用头像或半身像。小人是房间中的角色图，四个预览方向表示面朝哪里，不会修改人物身份或当前位置。

小人推荐四列、四行透明 PNG。四行依次向下、向左、向右、向上；每行四帧按“站立 → 左手右脚 → 站立 → 右手左脚”排列，格子为正方形、脚底对齐。第一帧用于停止时站立。仍兼容原 1–8 帧图集，已有自定义图片不自动改写；若原第一帧不是站立，应在绘图软件修改后重新上传。新示例图集按该顺序重新生成，来源哈希见原素材清单。

预览默认站立，点击“播放行走”才循环，停止、换人物、换分页、关闭或进入后台时停止预览。行走选帧按实际动画行进距离连续推进，四帧跨两格；每格保持 200 ms，不再对长路径压缩速度。保存命令后只刷新状态和交互按钮，路径播放前不先画终点，修复一格一格跳回的画面。摇杆松开后完成已保存的一步并站立，原碰撞、事件、重试和 SQLite 写入流程保留。

图片仍以原名册 ID 分开保存；异步文件读取完成前切换人物会丢弃该次未接受图片，不能落到另一个人物上。无需数据迁移，也不新增模型请求或业务库。未导入第三方运行代码；复用已有 Canvas、路径和图片验证接口，修改仅涉及显示与输入适配。

验收：114 项 Node、97 项 Python 通过；原视觉与摇杆浏览器回归通过。`tests/world-motion-browser.mjs` 实际记录 Canvas 选帧和插值位置，验证四帧、停止站立、无终点闪跳、分人物双类上传、延迟读取隔离、滚动关闭和重载保存。`tests/world-motion-android.mjs` 在专用 Android 11 / Chrome 83 WebView 上使用原生触屏和 screencap 验证摇杆、四帧、站立、分页、完整弹窗及滚动关闭，原签名覆盖安装保留合成数据。针对旧 WebView，弹窗显式固定在视口内，避免只检查 DOM 打开状态而漏掉弹窗被排到屏幕外的问题。模型调用均为零；未验证真机。

基线 `feat/world-joystick@d3d3fb0`，独立分支 `feat/world-visual-dialogue`。按确认的视觉稿实现暖木房间、三个人物、底部立绘对话、回放与头像菜单，保留既有世界、聊天、名册、模型配置、记忆与居民生活。

Android 文件上传边界：本轮原生触屏已打开系统 DocumentsUI，显示合成 PNG，但没有完成原生文件选择到保存的验收；完整上传/替换/保存/重载由手机浏览器脚本验证。不将该结果写成 Android 原生上传全流程已通过。

## 使用

进入世界后用左下摇杆移动，也可以点地板寻路。点击远处物品会走近；只有进入交互距离才出现“浇水、读书、开关灯、整理床铺、拉动窗帘”等按钮，按下后执行并保存。右上用户头像展开九个功能方块；世界记录、居民生活和移动对象等设置移入这里，原功能保留。世界页隐藏 API 悬浮球，模型连接仍可从菜单进入原设置。

点击人物，走近后打开底部对话。房间仍显示，摇杆收起。长回复可翻页，“重播本轮”读取所选已保存回复并调用原设备朗读；点击左下记录泡泡可查看旧消息并选中回看，不调用模型、不追加消息或事件。语音使用现有系统 TTS，并非录制音频或新增人物音色；设备缺少中文声音时沿用原错误提示。离开对话会取消朗读。

菜单“人物”选择现有名册人物或“我”，修改默认示例形象、导入最多八张对话立绘、选择默认立绘、导入四方向图集并预览。图集使用透明 PNG，四行依次下/左/右/上，每行 1–8 帧、正方形单帧。点击对话立绘可轮换已保存立绘；只有一张或尚无立绘时打开形象编辑页。已有名册头像仍可作为对话图，名册身份不变。当前提供导入、替换和缩放预览，不包含 App 内 AI 生图或逐像素绘画编辑器。

## 所有者与写入

| 模块 | 职责 |
|---|---|
| CharacterLooksModule / character-looks | 形象读取、候选验证、人物 ID 绑定；经原 LocalService 事务保存 `character_looks`，不改 Canon/Persona |
| world-core / world-scene-actions | 在场/附近/听众快照、方向、窗帘状态、已完成对话的有限行动接受与事件来源 |
| world-art / world-renderer | 资源加载、坐标投影、四方向选帧、房间和人物绘制；不写数据、不调用模型 |
| world-ui | 世界命令、近处按钮、菜单、已保存路径动画 |
| world-dialogue-ui | 原场景会话流式显示、台词分页、历史与系统朗读 |
| character-looks-ui | 导入校验与私有表单草稿、四方向预览、调用形象接口保存 |

新增 `GET/PATCH /character-looks/{id}`，仅允许名册 ID 或 user。世界投影附带形象，不把图片或形象元数据放进模型上下文。SQLite 仍为唯一业务底账；原浏览器 IndexedDB 接口不变。Android 的 `TLookAssets` 在同一 SQLite 中按内容哈希保存图片，单行原业务文档只保存资源引用，避免多立绘使 CursorWindow 溢出；读取接口和备份恢复为完整图片。图片写入、未引用资源清理、版本 CAS 与文档保存同事务提交或回滚，不新增外部文件底账。新增 `world.curtain`、`world.facing` 为可补齐字段，旧消息、事件和对话快照保留；旧轮次重试仍使用原接收时快照。

## 感知与聊天动作

当前房间没有内部分隔，`room_occupants` 列出所有在场居民；`nearby` 保留距用户三格内的交谈位置；`heard_by` 为说话者及距说话者三格内的居民。看见某人在场不授予他的私人记忆；对话事件只向实际听众提供来源权限。旧快照没有 heard_by 时沿用原双方知情规则。

模型可在完成回复末尾提出一条受限 `[世界行动:{"type":"interact","target_id":"window"}]`，只允许当前说话者操作已有地点。程序计算可达近处、移动/转向并交互。先在私有世界副本接受整套动作，再与完成对话一起原子保存；无效地点、冒用行动者、多条候选、未完成流或保存失败均不能制造完成动作。前台动画读取已保存路径，重启后的事实不依赖动画播放。`scene_action` 事件关联完成对话 request_id，区别于用户命令、自主居民行动和对话原话。重复请求不再执行动作。

当前是有限地点动作，不是任意自然语言旁白执行器；场景提示明确要求先表达打算，执行结果以事件为准。动作可能让人物走远，之后再次交谈仍按原距离规则走近。

## 素材与复用

四张生产 PNG 是本项目按文字规格经内置 image_gen 生成的原创示例：房间、三套四方向行走图集、三幅半身立绘、九枚菜单图标。逐文件尺寸、SHA256、生成简述和分发许可在 `frontend/assets/world/PROVENANCE.json`。私人参考截图不随源码或 APK 提供；生产素材未输入真实聊天或人物资料。PNG 与本项目源码一起分发。

保留已有 Alicization Town A*、邻近观察适配和运行锁，版本与许可仍见原 provenance。另核对同一 `1a33ba65d0af2134b369b1eb4eb68f45d2c817c4` 的 `server/web/js/game.js` 第 533–545 行移动/步态与 875–883 行方向选帧：借鉴方向和步态分离的方式。新图集为“行表示方向、列表示角色与步态”，不同于上游布局；接入现有 Canvas 与已保存路径，不整体导入 Node 页面、身份或上游美术。没有新增引擎或运行依赖。
