# 人物图片与连续行走 · 0.15.0

0.16.0 已在这一版本基础上增加单格上传、原图对齐和原生图片选择；当前用法与验收见 [单格小人图片](SINGLE_FRAME_SPRITES.md)。下文保留 0.15.0 的阶段说明。

世界右上头像 → 人物 → 选择人物 → 编辑皮肤。所有图片仍属于这个人物的这套皮肤；身份在原名册编辑，模型配置与记忆库不变。本机网页和独立 Android 共用规则，共同后端未新增形象接口。

## 上传与预览

站立行走默认使用三列四行 PNG：每行依次为迈腿 A、站立、迈腿 B，四行朝向下、左、右、上。48×48 的单格对应整图 144×192，也允许长方形格子。上传后显示四方向切帧表、每格尺寸；点格子检查朝向，播放检查步态，停止回到站立。循环为站立、迈腿 A、站立、迈腿 B，不会凭空生成缺失的画面。原四帧图、不同方向顺序和已有自定义图集保留；选择对应导入格式，其他布局在“调整图集”中设置。改变导入格式不会偷偷重切已经保存的图片。

表情立绘可以“添加表情”、命名并上传，缩略图标明对应表情；每套最多额外十六种表情、合计二十四张图片。旧八种表情和未分类图片继续读取，未知情绪回退默认图。模型只接收自己的表情标识和名称，不接收图片数据。

交互动作分为物品交互与小人表情／姿态。物品交互保留原六种受世界规则约束的操作；小人动作可以添加名称、上传单行或四方向动画，每套最多十六项。上传挥手等姿态不会创建新家具、修改物品或替他人做事。删除自定义项会清理其图片，缺失资源不再提供给模型。

## 数据与动作边界

CharacterLooksModule 验证皮肤内新增可选 expressions（标识到名称）和 gestures（标识到名称、atlas）；旧数据不需要迁移。UI 保管编辑草稿，经原 PATCH 和统一事务提交。当前穿着与其他皮肤独立保留，同皮肤并发修改拒绝覆盖；比较忽略 JSON 对象的键顺序，避免第二次保存误报冲突。Android TLookAssets 对默认皮肤、额外皮肤的姿态图片均执行原 SQLite 图片抽取／恢复与垃圾回收，备份仍是完整文档。

已完成场景回复可提出独立一行 `[小人动作:已配置ID]`。世界模块核对当前说话人物及当前皮肤中的实际图集，再保存 gesture 事件、来源和实际观察者；重复轮次不重复执行，未知或未完成输出不产生动作。渲染器只播放已接受事件，姿态播一次后回到站立。物品交互仍走原距离／路径／操作校验，纯图片不获得任意执行能力。后台居民规则继续共用世界验证；本轮没有给后台新增姿态决策工具。

## 行走顿挫修复

原摇杆每格串行等待：保存 → 查询世界／资源 → 播放 200 ms 动画，因此保存耗时被叠加到每格之间。现在仅对摇杆的合法相邻格，将视觉预览与原保存事务并行；位置动画仍按 requestAnimationFrame 的真实经过时间线性插值，步态仍按累计距离选帧。每格动画和保存都完成后才接受下一格，没有积压的未来移动或第二写入口。

预览不是持久世界事实。保存失败立即停止预览，回到已保存位置，保留同请求重试入口；存储超过一格动画时长时会等待，避免显示未获确认的更多移动。松手最多完成当前相邻格，离开页面取消绘制，不创建后台移动。点击长距离寻路、场景动作和碰撞规则保留原保存后播放行为。

## 参考与复用

逐文件固定版本见 config/sprite-workshop-sources.json。本轮参考 RPG Maker 素材排列、Phaser 的输入／速度／动画分工，以及 Alicization Town 的 display/target 位置分离；未复制其引擎、代码或素材。Alicization Town game.js 的客户端插值按每帧固定距离更新，且依赖在线服务器目标位置，不能直接承担 Android 本机事务与跨刷新率运动；保留本项目已有按时间插值和统一 SQLite 写入。原上游寻路适配继续使用，未新增包依赖。

用户截图只用于理解布局，不进入源码或公开附件。当前默认美术没有重新绘制；行走流畅度、切图正确与素材本身的美术质量分别验证。
