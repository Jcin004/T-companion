## 要做成什么

进入某个人物的衣橱，选择整套穿搭，或组合素体、头发、上衣、下装/连衣裙、鞋和配饰。每个人物继续使用原人物 ID，整套上传的旧皮肤继续可穿。

既可以上传图片，也可以在锁定的素体上直接画衣服。先提供一个配好动作的服装版型：用户画图案、换颜色，预览四方向和迈步；改变袖型、裙摆等轮廓时，进入逐帧编辑。保存后可继续修改，也能作为允许 AI 选择的穿搭。

先做一套与暖木房间相配的母版人物和一件衣服，完成实际预览，再扩充款式。此前提过的 128×128 是试验画布；现在校准参考母版采用 64×96，文件画布、实际人物身高和世界显示比例分别记录。

用户最新调整的试稿方向（2026-10-24）：**约三头身，以新提供的像素小人参考图观感为准**。采用清晰的大块像素、深色轮廓、简化五官与平涂明暗，先检查正面站立样稿；比例待样稿认可后固定，随后四方向、迈步和服装沿用同一身体标尺。此前五头身及其微调范围不再作为制作要求。用户已认可正面素体预览并指定其轮廓作为固定参照。校准标准定为 64×96 画布、80 像素素体高、脚底中心 (32,88)，房间参考高度为画面宽度的 20%，见 [固定素体对照](FIXED_SPRITE_REFERENCE.md)。四方向、迈腿和首件衣服现已有试作，尚待美术定稿；头身比、图片画布与房间显示大小分别管理。私人截图仅用于风格参考，不进入公开源码或素材包。

## 服装怎样跟动作走

整套旧皮肤继续按原图集显示；组合穿搭先由模板合成缓存图集，世界继续读取统一的姿态接口。编辑工程与合成结果分开，缓存可重建。

每件部件声明适配的体型/模板版本、方向、动作与帧集合。身体和衣服共用世界运动给出的方向与帧进度，再应用模板规定的图层顺序、遮挡和锚点。朝背面时的长发、衣领和手臂不能沿用正面的固定层序。

第一版不做任意 PNG 自动变装：已有版型的花纹可通过预先绘制的蒙版/映射复用；改变衣服轮廓，或加入抱物、浇水等姿态，需要对应素材或人工修正。自动检查只能找缺帧、尺寸及模板冲突，不能证明衣服美术自然。

同一动作组共享画布、尺度和接地点基准，允许有记录的逐帧微调。不能每帧单独按非透明包围盒拉满画布，否则会忽大忽小；不能默认最低非透明像素就是脚底，裙摆、道具、阴影可能比脚更低。像素绘制和预览关闭平滑插值，编辑采用整数像素；房间适配缩放需实际检查像素密度。

## 数据与模块适配

以下是接口职责计划，不是已新增 API。

| 责任方 | 产生 / 校验 / 保存的内容 | 修改入口 |
|---|---|---|
| 人物模块 | 原人物 ID、Canon/Persona | 原名册编辑，绘图和换装不改人物身份 |
| 图片档案 | 原图、出处/许可、类型与版本；后续扩展可编辑工程和素材引用 | 档案命令验证大小、归属、引用后通过原事务保存；仍使用现有 SQLite 图片去重能力 |
| 形象/衣橱模块 | 体型、部件兼容、完整性、穿搭引用与 AI 权限 | 原形象接口增量扩展；草稿与可穿资源分开，编辑当前皮肤不覆盖其他皮肤 |
| 绘图编辑器 | 笔画、图层、临时选择、撤销历史、校准预览 | 只提交工程草稿/保存请求，不直接写 service.data；撤销历史有内存上限，按笔画聚合，不无限保存整张图快照 |
| 世界模块 | 已执行的换装与相关事件、当前穿着 | 用户/AI 都走相同校验和写入入口；模型只提出允许范围内的候选，不拥有图层或存储权限 |
| 渲染模块 | 按姿态合成/显示，可丢弃缓存 | 读取已验证资源、共享运动进度；不生成世界事实，不自行决定人物资料或记忆 |
| 持久化模块 | SQLite 唯一业务底账、事务/版本冲突与恢复 | 保留现有前后台 CAS/租约；原图、工程和资源引用作为同一可恢复保存，失败不能留下半套可穿资源 |

后台只能选择已经保存且通过完整性检查的穿搭，不运行隐藏绘图页面。素材缩略图与合成图由前台或可用宿主重建；无界面执行不以 Canvas 能否绘制决定一次换装是否成功。导出备份包含可编辑工程和引用资源，导入先校验再整体接受；旧工程、旧备份保留兼容读取。

UI 继续按“人物 → 衣橱 → 选穿搭 → 分类编辑”推进。固定返回/人物名称/保存，预览与素材格在同一工作区；皮肤管理不插入每个资源分页。区分人物表情立绘、世界小人动作、服装部件，不把它们合并成一个上传表单。

## 验证与交付安排

实施只用合成图片、隔离存档和模拟模型。阶段 2 覆盖透明留白、异形画布、四方向脚底与回退；阶段 4 覆盖双指缩放、指针取消、切人物时的未完成上传、撤销和保存失败；阶段 5 覆盖共用帧时钟、层序/遮罩及缺动作回退；阶段 6 覆盖未经授权穿搭、删除被引用素材、并发与重复命令。

每次产品阶段执行仓库 Node/Python 检查，按改动补浏览器及专用 Android 模拟器验收；发布时做格式、密钥、来源与原签名覆盖安装检查。模型不付费测试。初次调研仅核对 JSON、来源哈希和提交快照；阶段 1、2 的实际 APK 与验收见 [0.18.0 交付](SPRITE_CALIBRATION.md)。

## 绘画操作补充（2026-10-25；0.19.0 首版已验收）

画笔按固定网格整格填色，移动一个逻辑单位就填一格，不以连续圆形自由笔刷绘制。单位可选 1、2、4 个原图像素；网格原点固定，笔迹和橡皮都吸附同一套格子，拖得快时补齐经过的格子。切换单位不缩放或重采样已有笔迹。

辅助网格可开关，素体层锁定，衣服画在独立层。放大画布只是方便看清格子，与画笔单位分别控制；一次笔画一次撤销。手机先用放大/双指平移确认触控准确度，再接通后续动作模板。
