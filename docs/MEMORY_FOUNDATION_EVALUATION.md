# 记忆底座审查与隔离评测

日期：2026-10-20。应用基线：`e7a4374`；本阶段只增加评测和记录，不替换应用记忆、不迁移真实数据、不发布 APK。工作分支基于尚未合并的 `feat/memory-link-proposals`。

## 目标与阶段范围

产品目标是让人物在持续运行的世界里生活，用户与他们发生关系；其次是共同经历故事。聊天是交流窗口。记忆用于保存人物的经历、理解与未完事项。

本阶段完成现有模块审查和候选的首轮离线验证。生活状态、欲望、自主唤醒仍放在最小像素世界之后。已有手机独立聊天不因研究 Python 方案而改为依赖电脑。

## 架构适配结论

当前“聊天前自动召回、不额外请求聊天模型”已经存在，不应为这个能力重写整条链路。

| 当前模块 | 数据或职责 | 本阶段结论 |
|---|---|---|
| `frontend/local-service.js` | 联系人命令、生成轮次、事务、模型调用；发送前调用 `recallPlan` | 保留编排；以后接入外部召回时仍由它拥有取消、超时和本轮状态 |
| `frontend/local-queries.js` | 组装身份、历史、记忆与本次输入；预览共用组装函数 | 保留；外部材料不能另写一套 prompt 或绕过预览 |
| `frontend/memory-service.js` | 记忆提取、每日总结、自我分析与提交命令 | 已有独立模块；不把外部模型密钥、网络请求再散入记忆 UI |
| `frontend/memory-core.js` | 记录、开关、备份校验 | 保留旧结构；未来迁移必须可回退、保留来源及用户修改 |
| `frontend/memory-evidence.js` | 从已完成聊天投影来源，逐字验证引文 | 当前仅接受消息证据；世界事件需要独立来源类型，不能伪造一条聊天消息来入库 |
| `frontend/memory-recall.js` / `memory-lexical.js` | 来源有效性、人物过滤、BM25、有限关联扩展、预算、召回回执 | 已有本地自动召回；没有真实向量模型、世界事件源或自主浮现调度 |
| 记忆/关联/候选 UI | 卡片、来源、编辑、关系复核 | 沿现有命令接口读取；不因引入底座删除这些能力 |
| FastAPI 共同后端 | 独立 SQLite 数据源 | 不是本机记忆的同步副本；本阶段没有接入外部服务 |

具体维护问题：`LocalService` 仍承担较多编排，但已有独立的来源、检索、查询与写入模块，不适合整体重写。`MemoryModule.schedule()` 使用单个 timer，新会话可取消上一人物待处理任务，不能将其当作多人物后台调度器。以后世界运行应拥有自己的任务生命周期，不扩建这个聊天 timer。

拟接入的数据流：世界事件/聊天原文 → 该人物有依据获知的来源 → 个人记忆写入 → 请求前召回 → 来源与范围验证 → 现有上下文组装 → 一次正常聊天请求。原文由各自领域拥有，记忆不反向改原文或名册。剧情独立分区；被提及不等于有知情权。

## 同一夹具的结果

使用四条虚构经历：林的兰花花盆待办、已经取回的包裹、雨独自知道的钥匙、仅属于剧情的龙蛋。各方案读取相同正文与查询，不读取真实聊天或 API 配置，不使用付费模型。

| 七个共同检查 | 当前应用 | Latent 原始候选层 | OB 原生关键词层 |
|---|---|---|---|
| 兰花、包裹各只返回预期条目（2 项） | 2/2 | 0/2：目标均排第一，但额外返回另一条 | 2/2 |
| 私人钥匙不跨人物、拥有者能找回（2 项） | 2/2 | 2/2 | 2/2 |
| 剧情不串入日常、剧情库可找回（2 项） | 2/2 | 2/2 | 2/2 |
| 没有的潜艇记忆返回空（1 项） | 1/1 | 1/1 | 1/1 |

另一个探索查询“植物容器坏了之后有什么待办？”在三套**无向量**配置下均未找到兰花条目。它是能力探针，单独报告，不隐藏、不计作必过回归项。不能用假向量的通过证明真实语义效果。

额外检查：当前应用的存储重载、停用排除、一次模拟聊天请求携带记忆通过，总计 10/10。Latent 的磁盘重读、查询不改文件/权重、撤回排除、零联网尝试通过，连同共同项为 10/12。OB 的磁盘重读、查询不改文件、`dont_surface` 不阻止显式搜索、归档排除、零联网尝试通过，总计 12/12。各方案额外项不同，**总数不是质量排名**。

解释与范围：

- Latent 测的是 `retrieve_candidates()`，不是最终自动浮现交付；关联扩展多返回候选不能直接推断为最终 prompt 污染。下一步须用相同夹具验证正式 hook 的最终交付，不修改期望值来消除本轮失败。
- 人物/剧情隔离由评测宿主分配独立存储。当前应用用独立测试人物代表剧情分区。结果不证明产品已有剧情隔离，也不证明上游有原生多人物权限系统。接入时不得把多个角色混进一个库。
- 重载是新建对象并重读存储，不是操作系统重启/进程崩溃恢复测试。
- 检查检索内容，不让聊天模型回答“知道不知道”；没有验证真实回答质量或记忆自动提取质量。
- Python worker 禁止 socket 连接并记录尝试数，两个候选均为 0；当前应用使用注入的模拟聊天传输。
- 语义测试未执行：本机没有现成 Ollama，本阶段未下载嵌入模型，也没有使用真实云端向量服务。

Latent 独立验证：`memory_retrieval.py --selftest`、`session_recall.py --selftest`、`passive_recall.py --selftest` 通过；`tests/passive_facts_test.py` 的 54 项测试通过，使用上游假向量与虚构事实。`session_recall` 会输出日志写入失败的 `FileNotFoundError` 提示，程序以 0 退出，自检通过；本轮未追查该提示的原因。

现有回归：本轮添加共享夹具回归后，`npm test` 为 74 项通过；后端 `pytest -q -W error` 为 91 项通过。没有界面、持久化格式、原生插件或 APK 变更，不将这些检查称为真机验收。

## 如何重复运行

只检查当前应用（随 `npm test` 自动执行）：

```powershell
node scripts/evaluate-local-memory.mjs
python scripts/evaluate-memory.py --output artifacts/memory-evaluation-local.json
```

候选评测：在独立虚拟环境安装 `scripts/requirements-memory-evaluation.txt`，分别获取上表固定提交的 GitHub 源码 ZIP 并解压，通过参数传入目录。本次指纹基于 ZIP 原始字节；Git 检出若转换了换行，核验会拒绝。上游不是本项目的运行依赖。

```powershell
python scripts/evaluate-memory.py --latent-source <Latent源码目录> --ombre-source <OB源码目录> --output artifacts/memory-evaluation.json
```

输出报告包含每条期望、实际结果、探针、执行配置与退出码。存在必过项失败时脚本返回 1；本次完整对比因 Latent 两个严格候选精度项未通过而返回 1，这是报告中的实际发现。不会把候选失败伪装成评测工具成功。输出目录 `artifacts/` 已忽略，不提交机器路径或上游原始日志。

## 决策与下一阶段验收

优先以 **OB 作为可选个人记忆服务原型**，保留手机本地记忆；此选择基于其现成的记忆状态、管理接口、许可与本轮基本接口验证，不代表语义质量已经优于其他候选。Latent 的 hook 机制继续作为逐轮交付候选，不同时启用三套独立写入和召回管线。SullyOS 优先用于本机流程适配，不能整套复制进不同架构后当作完成集成。

下一小阶段只做一个可回退的接入原型：

- [ ] 检查 OB 的现有 HTTP/MCP 能力，接到现有请求组装前；外部配置默认关闭。
- [ ] 角色与日常/剧情分区由宿主明确路由；请求不能自由选择别人的库。
- [ ] 外部召回超时或失败显示准确状态；保留当前本地模式和取消能力，不重复注入同一来源。
- [ ] 用一个真实本地嵌入模型补跑换说法、无答案及弱相关干扰集；小样本通过也不冒充成熟度证明。
- [ ] 单独验证开场未完事项与逐轮相关回忆；不把 OB 的 SessionStart hook 宣称为逐轮 hook。
- [ ] 在 Latent 正式 hook 下验证共同夹具、过期/重复记忆和临时注入；不把原始候选直接塞给模型。
- [ ] 日常和剧情来源能追溯，模型输出不反向改 Canon；迁移前保留导出与回退路径。

达到这些条件即可进入最小世界事件与像素场景，不等待复杂记忆网可视化、全面衰减或大量管理按钮。
