# 运行日志应用

桌面 → 运行日志。与聊天、外观、设置分别进入，不加入聊天气泡或模型提示词。

复用本仓库 `buildContext`、`LocalService.callModel` 和导出适配器。参照 SullyOS 的分类捕获、上下文开关、脱敏和限容设计，独立实现适用于当前原生 JavaScript / Capacitor 架构的日志模块。

## 查看内容

- 模型请求：请求标识、会话、模型、连接、发送消息数、字符数、耗时、回复字符数、完成/失败/取消/中断状态。
- 实际上下文：在真正调用模型的位置记录 system、历史与当前 user 消息；共同后端模式由服务器在调用前返回实际快照，旧后端无法提供快照时明确保留说明。
- 待发送预览：复用当前聊天的上下文构建器，包含草稿；固定概率候选在发送时确定，最终以实际请求快照为准。共同后端暂不预览未发送草稿。
- 报错：界面异常、请求失败、更新失败；共同后端额外返回异常类型和 HTTP 状态，不返回含敏感信息的服务商原始异常。
- 系统：启动、页面显示/关闭、网络变化、前后台变化。
- 更新：检查结果、校验完成、权限页/安装器打开、失败原因。

“记录新请求的聊天上下文”默认开启，可关闭；关闭后仍记录请求状态和错误，旧记录不变。日志只保存在本机，不自动上传。导出按钮明确提示可能包含聊天原文；用户可清空。预览不写日志。

## 存储与边界

Android 在现有 SQLite 中添加独立 `diagnostics` 表，不改变原 `documents` 聊天数据。浏览器使用独立 IndexedDB。普通聊天备份不包含诊断日志，恢复聊天也不导入日志。日志上限为 100 条、约 100 万字符；超过单条 35 万字符的上下文省略全文并明确标记，不伪装成完整快照。持久化失败降级为内存并显示提示，不影响聊天。

不记录请求头与 API 凭据；按敏感字段、Bearer、常见密钥格式、URL 凭据参数和运行期已知密钥进行隐藏。Android Keystore 不为日志读取密钥。完整上下文仍是私人聊天内容，导出后应由用户决定分享范围。该应用查看 T- 自己的诊断记录，不读取整台手机的系统日志；系统杀进程后未完成的请求显示“中断，结果未确认”。

## 验收

- 16 项 Node 测试：新增真实发送上下文一致性、失败状态、密钥隐藏、限容、重启、关闭上下文和存储失败降级。
- 85 项 Python 测试：包含后端上下文快照与实际模型参数一致，以及默认不返回全文。
- 浏览器实测：独立桌面入口、当前草稿预览、401 报错、按类筛选、导出文件无测试密钥、关闭后不记录新全文、重载、清空。
- Android 模拟器实测：运行日志入口、原生 SQLite 写入/读取；更新器系统安装覆盖 0.4 → 0.5 后，原角色、2 条消息、设置及加密凭据完整保留。日志模块安装后再次比对原聊天数据与凭据，保持一致。没有进行真实手机或付费模型调用。
