# 世界对话记录、皮肤、表情与动作 · 0.14.0

0.14.2 的编辑入口已改为人物列表 → 皮肤卡片 → 三个独立分页，具体操作以 [人物衣橱](CHARACTER_WARDROBE_UI.md) 为准；本页保留 0.14.0 的数据、来源、模型呈现协议和历史验收。

基于 `fix/world-character-motion@d76cfe9`，在独立工作区、分支 `feat/world-expression-history` 开发。原工作区的 Android 更新恢复分支及未提交修改保留。

## 使用

世界右上头像 → 人物 → 选择人物 → 选择皮肤。每个人物各有自己的皮肤库，默认皮肤沿用旧版图片；可以添加、重命名、删除额外皮肤，或设为当前皮肤。打开“皮肤管理与 AI 选择”，开启该人物的自主换装，并逐套选择是否允许 AI 使用，最后保存。没有额外模型配置或生图请求。

同一套皮肤下分三类：

| 分页 | 上传内容 | 用途 |
|---|---|---|
| 表情立绘 | 平静、开心、难过、生气、害羞、惊讶、疲倦、担心的图片 | 底部对话框的半身/头像图；未分类图片仍可手动切换 |
| 站立 / 行走 | 可配置列数、行数、方向行、站立帧、播放顺序的 PNG | 房间里的像素小人；支持三帧和四帧，不强制正方形格子 |
| 交互动作 | 浇水、翻书、阅读、整理床铺、开关灯、拉窗帘的独立 PNG | 程序完成对应房间交互后播放；可单行或配置方向行 |

图片从各分页的上传入口添加/替换；在绘图软件中修改后重新上传。App 提供资源配置与预览，不包含像素绘画软件。当前房间已有六类交互；示例中的挖矿、收获等需要实际地点和规则支持，单独上传动画不会制造这些世界事实。

方向按“小人的脸朝屏幕哪边”填写，行与帧均从 1 开始。图集模板包括：

- 四帧，下 / 左 / 右 / 上：保留原版约定。
- 四帧，下 / 右 / 上 / 左：适配另一种常用排列。
- 三帧，中间站立：站立帧 2，播放顺序 `2,1,2,3`。
- 单行交互：各方向共用这一行，按帧号顺序播放。

用户可修改每个方向对应行和站立帧，上传前填写；已有图片修改布局后按“应用方向与帧设置”。长方形单帧保持宽高比例。预览停止时使用配置的站立帧，不猜测图片中的四肢。用户提供的带水印和标注示例仅用于理解格式，未放进源码或 APK。

对话打开后房间保持原高度，底部对话覆盖其上；双方会朝向彼此。模型可在每段前输出已配置的 `[情绪:happy]` 等标记，界面为该段选择对应立绘；缺少图片时使用平静/默认图。翻页跟随各段表情，点击立绘仍可手动切图。立绘情绪和语音音色分开，本轮没有新增情绪语音合成。

## 全局对话记录与记忆

左下记录泡泡，或头像菜单 → 对话记录，查看世界内所有场景对话和居民彼此交流。支持人物筛选、文字搜索、游标加载。线上私聊仍在原聊天 App 中。查看全局记录不授予任何居民新的知识。

记录中显示原话、参与者、事件来源 ID 和对应记忆标题；语音段有“重新播放语音”，读取已保存台词，经原设备 TTS 朗读，不请求模型、不写新消息。删除了“回看这几句”按钮，底部对话原有翻页和本轮重播保留。

当前来源有两种：`chat_message` 由消息 ID 与逐字引文定位；`world_event` 由稳定事件 ID、实际观察记录和逐字引文定位。完成的场景轮次同时有原始消息和世界对话事件，居民交流直接使用世界事件。经历自动整理仍由既有居民生活开关、阈值、预算和 MemoryModule/OB 管理。

“删除对话与对应记忆”经确认后在同一个 SQLite 文档事务内：

1. 场景对话按整轮删除；居民交流按选中的发言事件删除。
2. 清空来源原话并标记删除，保留 ID 与请求回执，防止刷新、重试或重启重新执行。
3. 删除当前证据或旧版本引用这些来源的记忆卡，以及引用消息的总结；清理这些卡片的有向关联和候选。整张派生卡删除，不仅摘掉引文后保留未经支持的正文。
4. 关联主动分享一并清空；引用被删来源的待处理任务及响应不可继续接受，相关临时计划清理。
5. OB 使用剩余卡片重新同步。保存失败时原话、记忆和版本一起回滚；下一次召回重新校验缓存。

已执行的移动、浇水、换装等仍是独立世界事实，保留相应事件与当前状态。名册 Canon/Persona 和无关聊天/记忆不受删除影响。诊断日志为另一种私人数据，本功能不代替日志管理中的清理。

## 模块、接口与执行

| 模块 | 产生、读取和修改入口 |
|---|---|
| character-looks | 绑定原名册 ID 的皮肤、图片、方向元数据与 AI 允许范围；`GET/PATCH /character-looks/{id}`，原 LocalService 事务写入 |
| scene-presentation | 读取明确的显示标记，保持代码示例字面内容；不调用模型、存储或世界命令 |
| world-core / WorldModule | 面对面朝向、已完成回复提出的换装、实际世界事实与观察记录；保留已有移动和家具规则 |
| resident-life-core / headless | 同一预算内提出 `change_skin`；复用前台和 Worker 的请求预留、响应接受、CAS/租约与取消 |
| world-history | 全局只读投影、搜索游标、对话删除与来源撤销；`GET /world-history?owner=&q=&before=`、`DELETE /world-history/{id}` |
| memory-source-deletion | 记忆领域清理依赖卡片、版本、总结和关联，其他模块不直接改写记忆解释 |
| world-history-ui / world-dialogue-ui | 提交查询/删除、朗读已保存台词、显示表情；不直接改业务数据 |
| world-art / TLookAssets | 方向/帧选取与渲染；同一 SQLite 存多皮肤、表情、动作图片引用，原子去重与清理 |

模型只收到本人物允许的皮肤 ID/名称及表情 ID，不发送图片或其他人物的私有身份、记忆。场景完成回复中的 `[换装:皮肤ID]` 由程序校验，已用皮肤、越权、未知或重复候选均不产生换装事实。后台居民可提出同样的 `change_skin` 候选；不增加单独的分类/换装模型调用。表情标记用于当前显示，既不覆盖身份，也不自动成为长期情绪。

旧形象记录自动补齐空皮肤库、默认皮肤和关闭的自主换装；不重写原图片。旧图集继续使用原行序与第一帧站立。新增加的皮肤/动作字段应由新版读取；更新前可以使用原备份功能保留旧版快照，不承诺旧 APK 能识别新资源配置。
