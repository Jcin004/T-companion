# 0.8.1 设置收尾（2026-10-18）

## 问题与修复

上下文条数的业务规则原本支持全局与联系人覆盖，但继承模式禁用了输入框。现在全局和当前聊天均使用数字键盘文本输入，非空整数经原 context-policy 校验为 0–2000；直接编辑当前聊天会切为独立设置，选“跟随全局”则恢复默认值。空值、负数、小数和超范围不能静默保存为零。单联系人覆盖不改变其他人物。

风格、历史和名册子页原本关闭详情后丢失返回路径。现在使用原生 dialog close/cancel 生命周期恢复父页；按钮、Esc 和 Android 的既有 tGoBack 入口共用此路径。返回不重建父表单，未保存备注和范围保留；跳到消息或退出聊天清除返回关系，不重新弹窗。不增加业务数据或迁移。

## 职责检查

| 范围 | 当前所有者 | 本轮结果 |
|---|---|---|
| 模型预设与分组界面 | model-profiles-ui | 从混合 preferences-ui 迁移；仍走原连接/凭据接口 |
| 外观界面 | appearance-ui | 从混合 preferences-ui 迁移；原导出保持兼容 |
| 上下文和聊天表达界面 | chat-settings-ui | 详情、范围与动作设置共用一处实现；校验仍由 context-policy/chat-style 拥有 |
| 子页返回 | dialog-navigation | 统一记录父页，沿用原生 dialog，无第三方导航框架 |
| 本机事务和持久化 | LocalService/平台适配 | 保持现有接口、格式及事务，不因界面拆分重写 |
| 个人记忆 | MemoryModule/recallPlan | 保留已有来源、标签与关联召回 |
| 群像 | 未来像素世界领域 | 多人事件、群聊、社会关系和世界运行一起规划，不提前加入聊天模块 |

preferences-ui 是兼容组合入口，app.js 仍承担聊天导航、历史和部分名册展示。index.html 保存各 App 的静态外壳，不能将同页 HTML 误认为共享业务所有权。此轮没有宣称所有旧大文件都已拆完。

## 复用选择

优先复用项目已有的验证器、联系人命令、保存事务、风格规则、Capacitor 返回入口与原生 dialog；没有新增运行依赖。既有 float SSE/JSON、Serein 检索和 jsonrepair 保持不变。对照 float/SullyOS 的分区设置与按聊天配置结构，不导入其整套 React/Next 状态系统来修复当前 JavaScript 表单。第三方是否有相应测试需逐项核验，不能仅凭仓库来源假定质量。未导入新的第三方文件，因此没有新增来源许可条目。

## 后续维护范围

- LocalService 仍有命令、传输与平台适配职责；以后修改存储或传输时沿真实平台差异提取，不先复制另一套服务。
- SQLite 中业务文档仍整份保存；大量消息和世界事件前先测量，再决定实体化存储与迁移。
- 日志业务与 UI 仍在 diagnostics.js；扩展日志入口时再分离。
- 多标签页/实例未协调写入；未来同步需要明确版本与冲突规则。
- 自动整理的单计时器不能承担自主世界调度；随像素世界之后的任务系统处理。
- 本机与 Python 共同后端能力不同；本次 UI 范围输入仍使用各自现有接口，聊天风格仍仅本机。
- 发布链仍需审核、整合各开发 PR；默认 GitHub 渠道在用户手机上的网络可达性不由本次 UI 改动解决。

## 验收入口

tests/chat-settings-browser.mjs 使用两个隔离人物验证全局 37、单聊天 7、恢复继承及 0 条的实际模拟请求；刷新持久化、非法值、返回/保存、父表单草稿、来源跳转和退出清理。既有 context、preferences、chat-editing、api-floating 流程回归验证接口与迁移后的行为。

Android 验证使用隔离模拟器和原签名安装包；实体手机键盘及返回键体验需用户试用。各项实际执行结果以交付 PR 为准。
